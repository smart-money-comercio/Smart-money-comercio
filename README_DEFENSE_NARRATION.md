# Defense program facts and concise narration — rules 24

The new defense-program profile extracts named programs, developmental or prototype stage, a company-reported completed flight test, a named customer, an explicitly identified existing prime contract and a future review gate. Each field retains its original sentence. It reads already admitted original release bodies within the existing request budget.

The profile separates existing contract context from a new award, obligated funding, recognized revenue and production readiness. Planned, negated, failed, speculative or explicitly historical tests cannot become completed current-program facts. Different programs or conflicting values prevent unscoped contract and review references from being attached. Existing capability-specific readers remain available when the new program profile does not fit.

New editions use evidence schema 10 for supported program releases and reader version 3. The opening pairs dated market observations with concrete facts from a selected original disclosure. It retains the distinction between a market move and a business explanation. Open-session and completed-session wording, incomplete index coverage and research-watchlist participation remain explicit. A program's next disclosed review can supply a useful business watch in place of a generic price-cause question.

Verified company price moves without selected disclosures or dated earnings context can share one paragraph and one disclosure check. Pending quote checks and issuer-specific results context remain separate. New Treasury narration names the auction date for each tenor without suspended hyphens or “respectively.”

The schema 2 episode export, source references and private review requirement remain. Opening source references point to the selected disclosure actually used in the takeaway. Reader versions 1–2 and evidence schemas 1–9 continue to reproduce saved editions, including the rules 23 report and narration fixture.
